## Как правильно читать эти числа

### Почему XGBoost силён (и что это означает)

XGBoost получает 86.7% Hit@1 — почти столько же, сколько GNN.  
**Это не недостаток GNN, а доказательство качества нашей feature engineering.**

Мы специально спроектировали 4 временных канала:
- `value` — текущее значение метрики
- `delta_short` — шаг за один тик
- **`delta_long` — отклонение от EMA-базелайна (30-шаговое скользящее среднее)**
- `rolling_var` — дисперсия за 5 шагов

`delta_long` — это и есть «сигнал неисправности». Инженерный результат всей Фазы 5  
(forensic audit, SNR-анализ, подбор амплитуд) в том, что `delta_long` RC-узла надёжно  
**превышает** `delta_long` любого здорового узла того же типа (rc>bg ≥ 75%).

Когда feature engineering настолько точна, даже дерево решений может найти порог.  
XGBoost использует **именно этот факт** — он, по сути, учит порог на `delta_long`.

### Что добавляет GNN поверх XGBoost

GNN выигрывает не только в абсолютном числе, но за счёт **структурных свойств**:

| Свойство | XGBoost | GNN |
|----------|:-------:|:---:|
| Использует соседей по графу | ✗ | ✓ (16 типов рёбер) |
| Отличает «жертву» от «корня» структурно | ✗ | ✓ |
| network_congestion Hit@1 | 97.7% | **100%** |
| gpu_thermal_throttle Hit@1 | 89.5% | **91.6%** |
| disk_full Hit@1 | 90.4% | **92.3%** |
| Не регрессирует ни на одном типе | ✗ (cpu_cache ↓) | ✓ |
| Объясняемость через attention weights | ✗ | ✓ (XAI) |

Ключевая разница — **network_congestion**: switch-узел сам по себе не аномален,  
аномальны его downstream-хосты. XGBoost видит только switch.x и иногда ошибается.  
GNN через message passing видит «switch ← (cpu#i аномален, gpu#i аномален, ...)»  
и уверенно ставит switch на первое место (**100% Hit@1**).

### Прогресс за время работы (история GNN)

| Этап | Hit@1 | Что изменилось |
|------|------:|----------------|
| GNN v4.4 (3 типа неисправностей) | ~72% | исходная версия |
| GNN v4.8 (9 типов, баг numpy/torch) | 70.1% | *артефакт split-бага* |
| GNN v4.9 (баг исправлен) | **63.3%** | честный результат, потолок SNR |
| **GNN v5a_40 (наша работа)** | **87.5%** | +24.2pp за счёт redesign |

**Главный научный вклад**: подъём с 63.3% → 87.5% (+24.2pp) путём:
- forensic audit SNR (диагностировали почему упёрлись в 63%)
- пересмотр амплитуд fault injection (7 типов из 9 улучшены)
- переход на global cross-entropy loss вместо per-type BCE
- SharedScorer с type embedding вместо раздельных голов
- исправление healthy_ratio mismatch (v5a_70 → v5a_40)

## Честность эксперимента

- **Одинаковый split**: `torch.randperm(seed=42)`, val = те же 900 графов, n_faulted = 534
- **Одинаковые метрики**: Hit@k/MRR, per-graph ranking (не binary classification accuracy)
- **Одинаковый n**: все методы оценивались на тех же 534 faulted val-графах
- **Baseline обучены на 3600 train-графах** — столько же видел GNN
- **XGBoost получил богатые признаки**: one-hot типа узла добавлен явно (у GNN этого нет)
- **GNN v4.9** взят из `reports/final_v49_fulltraining.md` (тот же val split)

## Дополнительный structural benchmark

После baseline-сравнения был добавлен отдельный `v6_topology_screen`, чтобы проверить не общую силу feature engineering, а именно графовую гипотезу. В этом benchmark локальный сигнал RC ослаблен, добавлены same-type decoys, а решающая информация переносится в согласованный паттерн топологически связанных жертв.

| Модель | Hit@1 | Hit@3 | MRR |
|--------|------:|------:|----:|
| XGBoost value-only | 28.0% | 69.3% | 0.533 |
| XGBoost temporal | 28.0% | 71.0% | 0.535 |
| MLP local-only | 25.3% | 73.0% | 0.516 |
| **GNN full graph** | **89.7%** | **99.7%** | **0.946** |
| GNN no-edge probe | 0.0% | 0.3% | 0.048 |
| GNN random-edge probe | 2.0% | 4.7% | 0.048 |
| XGBoost temporal + manual neighbors | 94.3% | 99.7% | 0.970 |

Этот результат меняет формулировку вывода. На `v5a_40` маленький разрыв между GNN и XGBoost означает, что temporal feature engineering получился очень сильным. На `v6_topology_screen` локальные baselines разваливаются, а GNN сохраняет 89.7% Hit@1, причём та же GNN без рёбер или со случайными рёбрами почти полностью теряет качество. Это прямое доказательство, что message passing использует структуру графа.

Ручной XGBoost с соседями остаётся сильным, потому что ему явно передали mean/max признаки соседей из `edge_index`. В дипломе его следует показывать как upper-bound для табличного подхода с ручной топологической инженерией: он работает, но требует заранее писать агрегацию под конкретную схему кластера, тогда как GNN учит агрегацию по рёбрам автоматически.
